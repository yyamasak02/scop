## 第II章 — AIに関する指針

### 背景

AI は今や、仲間（ピア）とともに大規模で難しいプロジェクトに取り組むための強力なコーディングパートナーです。あなたは技術面・非技術面の両方で AI を導いていくことになります。

AI ツールは効率や成果物の質を高めてくれますが、AI に頼らなくてもプロジェクトのどの部分も深く掘り下げられる状態でなければなりません。

AI パートナーはあなたを支えますが、十分な情報に基づいて技術的判断を下し、それを明確に説明・擁護する責任は常にあなた自身にあります。

### 主なメッセージ

- 成熟した責任ある AI の使い方を心がけること。
- 判断の責任を AI に負わせないこと。特に、AI があなたの目標・制約・チームの事情を把握していない場合は。
- 仲間との積極的な協力を通じて、創造性・革新性・人間による監督を保つこと。AI は既存のデータで学習しており、本当に新しいアイデアはほとんど生み出しません。
- 新しい潮流を把握し、新しい概念や技術に適応できるようにしておくこと。

### 学習者のルール

- 自分のプロジェクトの知的なリーダーシップを保ち、自分で十分に考えて判断すること。
- チームやピアの集合知を優先すること。
- AI 技術の進化について、自ら進んで情報を追うこと。

### このフェーズで得られるもの

- AI エンジニアリングのスキル
- 効率の向上
- 信頼性と品質の向上
- 先駆者の姿勢

### コメントと例

- ピアはトレードオフを見抜き、前提を問い直し、改善を助けてくれます。AI の最初の答えが最善とは限りません。効率・セキュリティ・実質的な価値のいずれかが欠けている場合があります。今こそ、ピアを頼るべきときです。
- AI はあなたを速くしますが、ピアはあなたをより良くします。協力、議論、互いへの問いかけが成功の鍵です。
- プロジェクトで AI をどう使ったかを透明にし、AI ツールが生成したものを明確に示すこと。

**良い例:**
API のユニットテストの生成を AI に手伝ってもらった。チームメイトとレビューし、エッジケース向けに調整した。時間の節約になり、二人とも新しいことを学べた。

**悪い例:**
プロジェクトのアーキテクチャ全体を AI に生成させた。「動く」けれど、ピアレビューや顧客の前で設計判断の説明を求められても答えられない。信用を失い、不合格になる。

## 第III章 — 課題

### III.1 気分よくやろう

気分がいいと、やっぱりいいものです。だから、気分が上がる小さなアプリを作りましょう。

また、このプロジェクトは知的な意味でしっかり鍛えられます。面白くするために、いくつかの制約が設けられています。

### III.2 やるべきこと

あなたのミッションは、Blender などのモデリングツールで作成された **3Dオブジェクトを表示する小さなプログラム** を作ることです。

この3Dオブジェクトは `.obj` ファイルに保存されています。パースと正しいレンダリングはあなた自身が実装する責任があります。

ウィンドウ内で、3Dオブジェクトは **透視投影**（遠くのものが小さく見える）で表示されなければなりません。また、キーボードやマウスなど好きな入力方法で、**3つの主対称軸（原点はオブジェクトの中心）まわりに回転・平行移動** できなければなりません。

様々な色を使って、オブジェクトの異なる面が視覚的に区別できるようにしてください（`.obj` で定義された3D面単位でも、三角形分割する場合は三角形単位でも構いません）。

最後に、専用のキー（または任意の入力方法）を押すとオブジェクトにテクスチャが適用されます。同じキーをもう一度押すと、カラー表示に戻ります。急な切り替えのない、**スムーズなトランジション**が求められます。

---

#### 技術的な制約

- 使用言語は自由です（C / C++ / Rust が推奨）。
- OpenGL、Vulkan、Metal のいずれかを選べます。
- プロジェクトの実行に必要な依存関係を確認し、必要ならインストールまで行う**ワンライナーのコマンド**を用意してください（例: C プロジェクトなら標準的な Makefile）。
- 外部ライブラリはウィンドウおよびイベント管理に**のみ**使用可能です。
- 3Dオブジェクトの読み込み、行列の生成、シェーダーの読み込みには**外部ライブラリの使用は禁止**です。OpenGL / Vulkan / Metal の API を使って自分で実装してください。

---

## 第IV章 — README の要件

Git リポジトリのルートに `README.md` を用意してください。プロジェクトを知らない人（ピア、スタッフ、採用担当者など）が、何のプロジェクトで、どう実行し、詳しい情報をどこで得られるかを素早く理解できるようにするためのものです。

`README.md` には少なくとも以下を含めてください:

- 1行目は斜体で、次の文にすること: *This project has been created as part of the 42 curriculum by `<login1>[, <login2>[, <login3>[...]]]`.*
- 「**Description**」セクション: プロジェクトの目的と概要を明確に示す。
- 「**Instructions**」セクション: コンパイル・インストール・実行に関する必要な情報。
- 「**Resources**」セクション: トピックに関する定番の参考資料（ドキュメント、記事、チュートリアルなど）の一覧と、**AI をどう使ったか**（どのタスク・プロジェクトのどの部分で使ったか）の説明。

> プロジェクトによっては追加のセクション（使用例、機能一覧、技術的な選択など）が求められる場合があります。必要な追加事項は以下に明記されます。

## 第V章 — ボーナス

ボーナス機能の候補は以下のとおりです:

- **[10点]** 凹型や非平面など、複雑な `.obj` ファイルの適切な処理。リソースに含まれるティーポットは2バージョンあります: 一方はオリジナルで、エッジに少し変わったアーティファクトが現れます。もう一方はBlenderから再エクスポートされたもの（手動調整なし）で、ソフトウェアによって少し正規化されています。最初のバージョンを正しくレンダリングしてみてください。
- **[5点]** テクスチャをより自然に適用する — 一部の面に目立つ引き伸ばしが出ないように！
- **[10点]** さらに印象的な機能を、自分で考えて追加してみましょう。

> **警告:** ボーナスの評価は、必須パートが**完璧**な場合にのみ行われます。「完璧」とは、すべての要件が完成し、完璧に動作することを意味します。必須機能が一つでも欠けていれば、ボーナスは一切評価されません。
