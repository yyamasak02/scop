## 実践
変換の理論をひと通り説明したので、今度はその知識を実際にどう活かすかを見ていきます。OpenGL には行列やベクトルに関する機能は組み込まれていないため、自分で数学クラスや関数を定義しなければなりません。この本では、細かな数学の話はいったん抽象化して、あらかじめ用意された数学ライブラリを使うことにします。幸い、OpenGL 向けに作られた使いやすい数学ライブラリとして GLM があります。

## GLM
GLM は OpenGL Mathematics の略で、ヘッダーオンリーのライブラリです。つまり、必要なヘッダーファイルを include するだけでよく、リンクやコンパイル作業は必要ありません。GLM は公式サイトからダウンロードできます。ヘッダーファイルのルートディレクトリを includes フォルダにコピーして、さっそく使ってみましょう。

GLM のうち、私たちが必要とする機能の大半は次の3つのヘッダーファイルにあります。

```cpp
#include <glm/glm.hpp>
#include <glm/gtc/matrix_transform.hpp>
#include <glm/gtc/type_ptr.hpp>
```

GLM で学んだ変換の知識を使って、`(1,0,0)` のベクトルを `(1,1,0)` だけ平行移動してみましょう。なお、ここでは同次座標を `1.0` にした `glm::vec4` として定義します。

```cpp
glm::vec4 vec(1.0f, 0.0f, 0.0f, 1.0f);
glm::mat4 trans = glm::mat4(1.0f);
trans = glm::translate(trans, glm::vec3(1.0f, 1.0f, 0.0f));
vec = trans * vec;
std::cout << vec.x << vec.y << vec.z << std::endl;
```

まず、GLM に組み込まれているベクトルクラスを使って `vec` という名前のベクトルを定義します。次に `mat4` を定義し、行列の対角成分を `1.0` にして明示的に単位行列で初期化します。もし単位行列で初期化しなければ、その行列はヌル行列、つまりすべての要素が 0 の行列になってしまい、その後の行列演算もすべてヌル行列になってしまいます。

次の手順では、単位行列を `glm::translate` 関数に平行移動ベクトルと一緒に渡して変換行列を作ります。このとき、与えた行列に平行移動行列を掛けた結果が返されます。

そのあと、ベクトルに変換行列を掛けて結果を出力します。もし行列の平行移動の仕組みを覚えていれば、結果のベクトルは `(1+1, 0+1, 0+0)`、つまり `(2,1,0)` になるはずです。このコードは `210` を出力するので、平行移動行列はきちんと働いています。

では、もう少し面白いことをして、前の章のコンテナオブジェクトを拡大縮小してから回転させてみましょう。

```cpp
glm::mat4 trans = glm::mat4(1.0f);
trans = glm::rotate(trans, glm::radians(90.0f), glm::vec3(0.0, 0.0, 1.0));
trans = glm::scale(trans, glm::vec3(0.5, 0.5, 0.5));
```

まず各軸方向に 0.5 倍でコンテナを縮小し、そのあと Z 軸まわりに 90 度回転させます。GLM は角度をラジアンで受け取るので、`glm::radians` を使って度からラジアンへ変換しています。テクスチャ付きの長方形は XY 平面上にあるので、Z 軸まわりに回転させたいわけです。回転軸は単位ベクトルである必要があるので、X 軸・Y 軸・Z 軸以外の軸で回転させるなら、先に正規化しておいてください。GLM の各関数に行列を渡すと、GLM が自動的に行列同士を掛け合わせ、すべての変換をまとめた変換行列を作ってくれます。

次の大きな疑問は、変換行列をどうやってシェーダーに渡すかです。少し前に、GLSL にも `mat4` 型があると触れました。そこで頂点シェーダーを修正し、`mat4` の uniform 変数を受け取って、位置ベクトルにその行列を掛けるようにします。

```glsl
#version 330 core
layout (location = 0) in vec3 aPos;
layout (location = 1) in vec2 aTexCoord;

out vec2 TexCoord;
  
uniform mat4 transform;

void main()
{
    gl_Position = transform * vec4(aPos, 1.0f);
    TexCoord = vec2(aTexCoord.x, aTexCoord.y);
}
```

GLSL には `mat2` と `mat3` もあり、ベクトルと同じようにスウィズル的な操作ができます。ここまで説明してきたすべての数学演算、たとえばスカラーと行列の積、行列とベクトルの積、行列同士の積は、行列型に対して使えます。特別な行列演算を使うときは、何が起きているのかをきちんと説明していきます。

uniform を追加し、`gl_Position` に渡す前に位置ベクトルへ変換行列を掛けました。これでコンテナは半分の大きさになり、90 度回転して左に傾いたはずです。ただし、まだ変換行列をシェーダーに渡す必要があります。

```cpp
unsigned int transformLoc = glGetUniformLocation(ourShader.ID, "transform");
glUniformMatrix4fv(transformLoc, 1, GL_FALSE, glm::value_ptr(trans));
```

まず uniform 変数の場所を問い合わせ、それから `Matrix4fv` を末尾に持つ `glUniform` 関数を使って行列データをシェーダーへ送ります。最初の引数は、もうおなじみの uniform の場所です。2つ目の引数は、送信したい行列の数で、ここでは 1 です。3つ目の引数は転置するかどうかを尋ねています。つまり行と列を入れ替えるかどうかです。OpenGL の開発者は内部的に column-major ordering と呼ばれる行列配置をよく使いますが、これは GLM の既定の配置と同じなので、転置する必要はありません。`GL_FALSE` のままで大丈夫です。最後の引数が実際の行列データですが、GLM は行列データを OpenGL の期待と必ずしも一致しない形式で保持しているため、まず `value_ptr` という GLM の組み込み関数でデータを変換します。

変換行列を作り、頂点シェーダーで uniform を宣言し、その行列をシェーダーへ送り、頂点座標を変換しました。結果は次のようになるはずです。

完璧です。コンテナは確かに左に傾き、しかも半分の大きさになっています。変換は成功しました。もう少し遊んで、コンテナを時間経過に合わせて回転させてみましょう。ついでに、ウィンドウの右下へ移動させます。時間経過でコンテナを回転させるには、毎フレーム更新が必要なので、レンダーループの中で変換行列を更新しなければなりません。角度を時間に応じて得るために、GLFW の時間関数を使います。

```cpp
glm::mat4 trans = glm::mat4(1.0f);
trans = glm::translate(trans, glm::vec3(0.5f, -0.5f, 0.0f));
trans = glm::rotate(trans, (float)glfwGetTime(), glm::vec3(0.0f, 0.0f, 1.0f));
```

前の例では変換行列はどこに定義してもよかったのですが、今回は回転を継続的に更新するため、毎回作り直さなければなりません。つまり、レンダーループの各反復で変換行列を再生成する必要があります。シーンを描画するときは、毎フレーム新しい値で再生成される変換行列が複数あるのが普通です。

ここではまず、コンテナを原点 `(0,0,0)` のまわりに回転させ、そのあとで回転後の姿を画面の右下へ移動させています。実際の変換順序は逆に読む必要があることを忘れないでください。コード上では先に平行移動してから後で回転しているように見えても、実際には先に回転が適用され、そのあとで平行移動が適用されます。こうした変換の組み合わせや、それがオブジェクトにどう作用するかを理解するのは簡単ではありません。こういう変換を実際に試してみれば、すぐに感覚がつかめるはずです。

これで、時間とともに回転する平行移動済みコンテナが完成しました。しかも、たった1つの変換行列だけで実現しています。これで、なぜ行列がグラフィックスの世界で強力な概念なのかが分かるはずです。無数の変換を定義して、それらを1つの行列にまとめ、それを好きなだけ再利用できます。こうした変換を頂点シェーダーで使えば、頂点データを再定義する手間を省けるうえ、データを毎回再送信しなくて済むので処理時間も節約できます。データの再送信はかなり遅いので、やるべきことは変換 uniform を更新するだけです。
